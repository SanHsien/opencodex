---
title: Windows 檔案權限逾時
description: 原子寫入如何在 icacls 暫時停滯後復原。
---

Windows 上，opencodex 在寫入設定、憑證或快取資料前，先用 `icacls` 保護空暫存檔。
權限強化失敗時，寫入失敗，原目的地內容保持原狀。

暫時的 `icacls` 逾時不必重新啟動 proxy。同一目的地的後續原子寫入可以嘗試復原一次。
如果復原也逾時，從該次復原開始的五分鐘內，後續寫入都會被拒絕。
五分鐘後的下一次寫入才會重新嘗試強化權限；沒有背景計時器。

如果先前的 `icacls` 子行程超過呼叫端的逾時保護、且尚未回收，
同一目的地的寫入會立即被拒絕，即使五分鐘已過也一樣；這不會消耗下一次復原額度。
健康的重疊寫入仍可執行，包括先前寫入正在強化空暫存檔或等待重新命名時。

每次復原都必須成功強化權限後才能發布檔案。權限拒絕仍會失敗，不會自動重試。
失敗寫入的清理不會消耗後續寫入的復原額度。不同目的地有各自獨立的逾時紀錄。
