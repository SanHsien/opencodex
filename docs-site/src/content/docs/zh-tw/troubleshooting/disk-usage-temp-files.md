---
title: 暫存檔造成的磁碟用量
description: responses-state.json.ocx.*.tmp 檔案是什麼、為何可能會累積，以及如何回收它們。
---

有些使用者在自己的 opencodex home（預設是 `~/.opencodex`）發現大量名稱類似
`responses-state.json.ocx.<pid>.<seq>.tmp` 的檔案，而且每次重開機後還會繼續
變多。

## 這些檔案是什麼

opencodex 會保留一份接續快取，讓 `previous_response_id` 鏈在 proxy 重新啟動
之後仍能延續。它以原子方式寫入這份快照：內容會先寫進一個暫存檔，再一步到位
取代真正的檔案。這正是為何寫入過程中的當機不會留下一份寫到一半的快照。

這個暫存檔通常會在替換完成的瞬間被移除。如果程序在這兩個步驟之間死掉，暫存檔
就會留下來。

由於快照是整份重寫，而不是附加寫入，每個檔案最大可達 24 MB。因此只要累積個幾
百個被遺棄的檔案，用量就會迅速增加。

**它們是快取，不是持久狀態。** 刪除它們唯一的代價，是進行中的對話鏈可能會重
新送一次情境。這些檔案裡不存在任何設定、憑證或歷史紀錄。

## 為何可能會累積

原本就有一套清理機制，但它只在一個時間點執行：proxy 第一次載入接續快取的時
候，也就是在該程序寫入任何東西*之前*。這帶來了兩個後果。

一個當機後重新啟動的 proxy，清理得太早，來不及看到前一個程序剛留下的暫存
檔——這裡有 15 分鐘的緩衝期，確保正在被寫入的檔案絕不會被動到——而它在剩下的
生命週期中再也不會回頭檢查。於是每次重新啟動，就多留下一個檔案。

更糟的是，這套清理機制會跳過任何擁有該檔案的程序 ID 仍然存活的檔案。重開機
後，作業系統經常會重新配發相同的程序 ID，於是一個舊檔案就可能被永久誤判為屬
於某個正在執行的程序。這就是為何用量成長的趨勢會跟著重開機走。

## opencodex 現在的做法

清理機制現在會依 proxy 一般的背景計時器重複執行，而不是只在啟動時跑一次，因
此執行中的 proxy 會自己回收被遺棄的檔案。它也會對早於本次開機時間的檔案略過
程序 ID 檢查，因為沒有任何正在執行的程序能擁有那些檔案。

安全規則維持不變：未滿 15 分鐘的檔案絕不會被移除，proxy 也絕不會移除自己正在
寫入的檔案。

## 快照多久寫一次

寫入採用去抖動處理，去抖動的時間取決於**最近一次實際寫入的快照**大小：當那份
檔案還小時，下一次寫入會排在變動後約兩秒；一旦接近 24 MB 上限，等待時間會拉
長到最多三十秒。因此一個剛長大的快取，還是會先經歷一次短等待——較長的節奏是
從那次寫入*之後*才開始套用。只有在這個程序已經把相同的位元組寫進同一個檔
案、該檔案在磁碟上仍然相符，而且——在 Windows 以外——其權限仍然僅限擁有者
時，才會略過一次刷新。一個全新的程序會把相同的快照重寫一次，而任何內容或權
限在 proxy 底下被動過的檔案，都會走強化路徑重寫，而不是放著不管。

每個一般的背景節奏最多執行一次完整的原子重寫。如果接續快取在寫入進行中又發
生變動，opencodex 會在正常的延遲節奏上排一次後續動作，而不是立即再重寫一次
整份快照。優雅關閉在進行中的請求排空之後，仍會維持有上限的重試行為，讓最終
快照能夠追上進度再結束程序。

這些機制合起來，讓寫入速率大致維持平坦，隨快取成長而增加，而不是每兩秒就重
新序列化並替換整份檔案。

優雅關閉會立即刷新，不會等計時器跑完，所以較長的等待時間主要是拉大了「強制
砍掉程序會遺失最近幾筆接續紀錄」這個視窗——而如上所述，那些終究只是快取。那
次刷新仍然是一次磁碟寫入，也可能像任何寫入一樣失敗，所以在一個已滿或唯讀的
磁碟區上關閉，仍可能遺失同樣的紀錄。

## 回收已經累積的檔案

如果 proxy 正在執行，這個過程會在一兩分鐘內自動完成。

如果 proxy**無法**啟動——這正是堆積成長最快的情況——請從命令列檢查並回收：

```bash
ocx doctor
```

「Response-state temp files」一節會回報有多少檔案可以回收、佔用了多少空
間。它只做回報，不會改動任何東西。

要實際移除它們：

```bash
ocx doctor --reclaim-response-temps
```

這兩個指令在沒有執行中的 proxy 時也能運作。目前被其他程序鎖住的檔案會被回
報，而不會被強制處理。它們會在下一次回收時重試——proxy 執行中就自動重試，否
則就是你下一次執行這個指令的時候。

如果積壓的數量太大，一次跑不完，該指令會說明還剩下多少檔案，方便你再跑一
次。

這裡涵蓋的專門是 response-state 快照的暫存檔。其他元件會寫出名稱類似的自有
暫存檔，那些不在這裡的處理範圍內。
